# SwapIP

**Расширение для Chrome, которое меняет IP-адрес и страну вашего браузера.**

Работает на бесплатных публичных прокси. Никаких VPN, подписок и отдельных программ —
всё внутри браузера, в одно нажатие.

В комплекте идёт Python-анализатор: он сам собирает прокси, выбрасывает брак и
записывает готовый список прямо внутрь расширения.

## Что это и зачем

Задача простая: зайти на сайт, который показывает твой IP, и увидеть **другой** IP
и **другую** страну.

Без прокси сделать это можно только через VPN-сервис: они стоят денег, требуют
отдельную программу и часто режут скорость. SwapIP использует бесплатные публичные
прокси, которые уже опубликованы в интернете, и подбирает рабочий автоматически.

**Главная сложность, которую проект решает:** бесплатные прокси — это мусор.
Из тысячи адресов работает несколько десятков, они умирают за минуты и часть из них
вредоносная. Наивное расширение ставит прокси и сразу ломает браузер. SwapIP сначала
**проверяет** прокси и только потом его включает, а дополнительно страхует браузер
тремя способами, чтобы сеть не пропала никогда.

### Кому подойдёт

- Хочу проверить, как выглядит сайт для другой страны (цены, баннеры, вёрстка)
- Хочу зайти на заблокированный по гео сайту
- Хочу анонимно проверить, как работает мой сайт или сервис
- Разработчик, которому нужно быстро подменить исходящий IP

### Кому НЕ подойдёт

- Нужна **настоящая** анонимность (бесплатные прокси её не дают, см. раздел
  [о бесплатных прокси](#что-нужно-знать-про-бесплатные-прокси))
- Нужна стабильность уровня «бизнес» — здесь прокси живут минутами
- Нужен обход блокировок сложнее, чем гео-блокировка (тогда нужен VPN)

## Быстрый старт (5 минут)

Нужны: Chrome, Python 3.9+ и Node.js 18+ (для тестов, не для работы).

### Шаг 1. Загрузить расширение

1. Открой в Chrome адрес `chrome://extensions`
2. В правом верхнем углу включи **Режим разработчика**
3. Нажми **Загрузить распакованное расширение**
4. Выбери папку **`extension`** из этого проекта
5. На карточке SwapIP нажми иконку 🔗 (закрепить) — так быстрее найти

### Шаг 2. Получить список прокси

Без анализатора расширение сразу попробует взять прокси из публичных источников,
но это ненадёжно. Лучше запустить анализатор:

```bash
cd analyzer
pip install -r requirements.txt
python main.py
```

В меню выбери **`[1]` Полный парсинг** и дождись конца (обычно 10–20 минут).

> **Подробности про каждый пункт меню — в разделе [Анализатор](#анализатор-подробно).**

### Шаг 3. Перезагрузить расширение

Вернись в `chrome://extensions` и нажми **⟳ Обновить** на карточке SwapIP.

Расширение прочитает список, который анализатор положил в
`extension/data/proxies.json`, и сразу будет им пользоваться.

> Именно для этого список пишется внутрь папки расширения: тот, кто поставит
> расширение, получит рабочие прокси без импорта, без настройки URL
> и вообще без Python.

### Шаг 4. Подключиться

Кликни по иконке SwapIP → **Подключиться** → зайди на [2ip.ru](https://2ip.ru).

IP и страна должны отличаться от твоих.

## Как пользоваться расширением

В popup три вкладки.

### ⚡ Главная

Карточка статуса, кнопка подключения и то, через кого сейчас идёт трафик.

| Что видно | Что значит |
|---|---|
| **Отключено** | Прямое соединение, твой настоящий IP |
| **Подключение…** | Расширение перебирает прокси и проверяет их. Показывается прогресс-бар |
| **Подключено** | Трафик идёт через прокси. Ниже — реальный выходной IP и страна |

Кнопка внизу:

- **Подключиться** — ищет живой прокси
- **Отмена** — прерывает поиск (появляется во время подбора)
- **Отключиться** — снимает прокси

Кнопка **⚡** рядом со статусом — быстрая проверка, что прокси ещё жив.

Кнопка **🆘 Сеть не работает — сбросить прокси** — аварийная. Разбираем её ниже.

### 📡 Серверы

Список прокси с задержкой, страной и провайдером. Клик по строке — подключиться
именно к этому серверу.

Можно фильтровать по протоколу (HTTP / SOCKS4 / SOCKS5) и сортировать по пингу
или по стране.

> Показываются только прокси с измеренной задержкой. После первого подключения
> расширение замеряет лучшие и они появляются здесь.

### 🌍 Страны

Список стран, где есть прокси, с их количеством и лучшей задержкой. Клик по стране
— подключиться к самому быстрому прокси этой страны.

Кнопка **⟳** обновляет список прокси. Кнопка **📦 Встроенный список** загружает
список, который был записан в расширение анализатором.

## Что такое режим fail-safe и как его выбрать

Это единственная настройка, которая требует осознанного выбора. Она в ⚙ → **Fail-safe**.

**Fail-safe включён (по умолчанию)** — прокси прописан как `PROXY …; DIRECT`.

- Прокси умер → браузер мгновенно продолжает работать напрямую
- Сеть **никогда** не пропадает
- Но: пока прокси мёртв, ты можешь какое-то время быть на своём настоящем IP

**Fail-safe выключен** — трафик идёт **только** через прокси.

- Настоящий IP не показывается **никогда**, даже если прокси сломался
- Сеть может пропасть, пока расширение ищет замену

### Что выбрать

| Ситуация | Рекомендация |
|---|---|
| Общее пользование, хочется чтобы всё работало | **Включить** (по умолчанию) |
| Нужно гарантированно не спалиться | **Выключить** |
| Работаете с чужими данными, важна приватность | **Выключить** |

Расширение не даёт остаться в неведении: оно запоминает твой реальный IP и каждую
минуту проверяет, не вернулся ли трафик на него. Если прокси умер и браузер откатился
на прямое соединение, расширение это замечает и переподключается само.

**Отдельная настройка «Разрешать прокси без поддержки HTTPS»** нужна только для отладки
и по умолчанию выключена. Такие прокси не умеют открывать защищённые сайты и ломают
браузер — оставляй выключенным.

## Настройки

Открываются по ⚙ в popup.

### URL списка прокси

Ссылка на JSON со списком прокси. Нужна, только если хочешь раздавать список
другим людям через интернет. Для личного использования оставь пустым.

### Режим загрузки

| Режим | Что делает |
|---|---|
| **Авто** | Пробует URL → встроенный список → публичные источники. Рекомендуется |
| **Только встроенный список** | Берёт прокси из `extension/data/proxies.json`. Работает без интернета |
| **Только кураторский список по URL** | Только по указанной ссылке |
| **Только публичные источники** | Качает свежие списки из интернета сам |

> В режиме «Авто» встроенный список имеет приоритет первые 24 часа, потом
> расширение добирает свежие прокси из публичных источников — бесплатные прокси
> стареют очень быстро.

### Таймаут проверки прокси

Сколько секунд ждать ответа от проверяемого прокси. По умолчанию 10 секунд.
Если у тебя медленный интернет — поставь 15000.

### Диагностика

Две кнопки для случаев, когда что-то пошло не так:

- **🆘 Аварийный сброс прокси** — снимает настройку прокси из самого браузера,
  что бы ни думало расширение
- **🔍 Проверить состояние прокси** — сверяет, совпадают ли настройки расширения
  и браузера, и если нашёл расхождение — чинит

## Если что-то пошло не так

### Пропала сеть

Это главная боль, которую проект специально лечит. Если всё-таки случилось:

1. Открой popup SwapIP
2. Нажми **🆘 Сеть не работает — сбросить прокси**

Кнопка снимает настройку прокси **из самого Chrome**, даже если расширение потеряло
свое состояние. Обычно этого достаточно.

**Если popup не открывается** — зайди в `chrome://extensions` → SwapIP →
**⚙ Настройки** → **🆘 Аварийный сброс прокси**.

> Такой случай теперь исправляется автоматически: каждые 5 минут расширение
> сверяет состояние браузера со своим и само снимает прокси, если они разошлись.

### Пишет «Ни один прокси не прошёл проверку»

**Это не поломка.** В публичных списках прямо сейчас может не быть ни одного
живого HTTPS-прокси. Проверить:

1. Пункт **⟳** во вкладке «Страны» — обновить список
2. **📦 Встроенный список** — если список старый, он протух
3. Подожди и попробуй позже — пулы живут минутами, картина меняется каждые полчаса

### Пишет «Список пуст»

Запусти анализатор (пункт `[1]`) и нажми ⟳ в `chrome://extensions`.

### Страна не меняется, но «Подключено»

Скорее всего, прокси жив, но трафик пошёл мимо него. Проверь:

- Не включён ли VPN или другой прокси в системе — они перебивают настройки
- **⚙** → отключи **fail-safe**, тогда прокси не сможет уйти в обход

### Убрать нерабочий прокси

Он сам уйдёт из активной ротации: каждые 3 минуты расширение проверяет текущий
прокси, после двух неудач переключается на следующий.

## Как это работает внутри

Три части, которые стоит понять, если захочешь что-то менять.

### Схема

```
  Публичные списки в интернете
           │
           │  scraper.py — скачивает и приводит к единому виду
           ▼
  analyzer/ (Python, на твоём ПК)
           │
           │  checker.py — проверяет HTTPS с проверкой сертификата
           │  storage.py — сливает с базой без дублей и пишет список
           ▼
  extension/data/proxies.json   ← список лежит ВНУТРИ расширения
           │
           │  пользователь жмёт ⟳ Обновить
           ▼
  Chrome
           │
           │  background.js ставит PAC и проверяет прокси перед включением
           ▼
  Интернет через прокси
```

### Почему список лежит внутри расширения

Чтобы **другой человек** после установки получил рабочие прокси сразу, без
Python, без импорта и без настройки URL. Ты собрал список у себя на ПК — он
уехал в пакет расширения вместе с кодом.

### Как расширение выбирает прокси

1. Берёт записи из списка, сортирует по задержке и истории успехов
2. Ставит **PAC в режиме trial**: через прокси уходит **только проверочный запрос**,
   весь остальной трафик идёт напрямую
3. Отправляет запрос на `ipwho.is` (и запасные адреса) и смотрит ответ
4. Если прокси ответил и вернул чужой IP — прокси рабочий
5. Только теперь ставит PAC в обычном режиме, прокси весь трафик
6. Каждую минуту проверяет текущий прокси, при смерти переключается

Ключевая идея — **шаг 2**. Благодаря ему нерабочий прокси проверяется, но не может
помешать пользователю работать в интернете.

## Почему раньше роняло сеть и что изменилось

Если тебя интересует история бага — вот что было не так и как это починено.

### Симптомы

- `ERR_CONNECTION_CLOSED` на любом защищённом сайте
- `NETERR_CERT_AUTHORITY_INVALID` — ошибка сертификата
- «Нажал Подключиться, окно висит, отмены нет»
- «Закрыл браузер — сеть заблокирована, ожила только после удаления расширения»

### Три причины

**1. Проверка шла по HTTP, а работает всё через HTTPS.**

Замер на живых данных: **34 прокси из 150 отвечали по HTTP, но ни один не работал
по HTTPS**. Старый анализатор проверял `http://httpbin.org/ip` и считал все 34
рабочими — именно эти прокси и ломали браузер на любом `https://`-сайте.

Поэтому проверка теперь всегда идёт по HTTPS. Так отсекаются прокси без поддержки
`CONNECT` (то есть неспособные открыть защищённый сайт).

**2. Проверка не смотрела на сертификаты.**

В коде стояло `ssl=False` — проверка TLS была отключена. Поэтому прокси,
подсовывающие свой сертификат (MITM), проходили как «рабочие», а потом Chrome
показывал ошибку сертификата. Теперь сертификат проверяется по-настоящему.

**3. Прокси включался раньше, чем проверялся. И его состояние могло «залипнуть».**

Порядок был: включить прокси для всего браузера → потом проверить. Мёртвый прокси
мгновенно ронял сеть. А если service worker Chrome успевал «заснуть» посреди
операции, настройка прокси оставалась включённой навсегда (эти настройки переживают
перезапуск браузера), а само расширение считало себя выключенным. Отсюда и
«сеть заблокирована, пока не удалишь расширение».

### Что сделано

| Проблема | Решение |
|---|---|
| Проверка роняла сеть | PAC в режиме trial: через прокси идёт только проверочный запрос |
| Прокси залипал при падении worker'а | Сверка состояния при старте, каждые 5 минут и через `chrome.proxy.onProxyError` |
| Сеть пропадала при смерти прокси | fail-safe PAC `PROXY …; DIRECT` + автопереподключение |
| Окно зависало без отмены | Прогресс-бар, кнопка «Отмена», ограничение времени проверки |
| Ошибки сертификата и CONNECT | Проверка по HTTPS с верификацией сертификата в анализаторе и фильтр по флагу `https` в расширении |
| Ничего не помогало | Кнопка 🆘 аварийного сброса в popup и в настройках |

## Анализатор: подробно

Менюшное приложение на Python, которое готовит список прокси.

```bash
cd analyzer
pip install -r requirements.txt
python main.py
```

### Пункты меню

| # | Что делает | Когда использовать |
|---|---|---|
| **1** | **Полный парсинг.** Скачивает прокси из 10 открытых источников и папки `proxies/`, проверяет каждый по HTTPS, определяет страну/провайдера/анонимность, сохраняет базу и записывает список в расширение | Первый раз и потом регулярно |
| **2** | **Перепроверка.** Проверяет только живые прокси и **добавляет результат к базе**, не перезаписывая её | Хочешь обновить список, не начиная с нуля |
| **3** | Инструкция, куда класть свои прокси | Непонятно, как добавить свои |
| **4** | Топ-50: скорость, страна, анонимность, провайдер | Хочешь посмотреть, что нашлось |
| **5** | Только экспорт готовой базы в расширение, без проверки | Уже проверил, хочешь пересобрать список |
| **6** | Очистить все данные | Начать с нуля |

### Свои прокси

Положи файлы в папку `analyzer/proxies/` — поддерживаются:

```
1.2.3.4:8080
http://1.2.3.4:8080
socks5://1.2.3.4:1080
http://user:pass@1.2.3.4:8080
```

Файлы `.txt` (по одному прокси в строке) и `.json` (массив строк или объектов).
После этого запусти пункт `[1]` — свои прокси попадут в общую проверку.

### Как не теряются старые прокси

Это отдельная задача: при повторной проверке старые записи не выбрасываются.

Файл `analyzer/data/valid_proxies.json` хранит **все** когда-либо найденные прокси.
У каждой записи:

| Поле | Значение |
|---|---|
| `alive` | Прошёл ли последнюю проверку |
| `checks` | Сколько раз проверялся |
| `first_seen` | Когда найден впервые |
| `last_seen` | Когда последний раз работал |
| `geo`, `anonymity` | Страна и анонимность. При слиянии берутся из старой записи, чтобы не тратить повторные запросы |

Правила слияния:

- Ключ записи — строка прокси. **Дубликатов не бывает** в принципе
- Если прокси есть и в старом, и в новом списке — берутся свежие измерения,
  но гео и анонимность сохраняются
- Прокси, которые не попали в новый результат, **не удаляются**, а помечаются
  `alive: false` и уходят в конец списка
- В расширение попадают **только живые**

Если нужно наоборот — выбрасывать всё, что не прошло проверку, — поставь
`MERGE_KEEP_OLD = False` в `analyzer/config.py`.

### Куда пишется результат

Каждый прогон пунктов `[1]`, `[2]` и `[5]` создаёт два файла:

| Файл | Зачем |
|---|---|
| `analyzer/data/extension_proxies.json` | Для публикации по URL |
| **`extension/data/proxies.json`** | **Внутри расширения** — отсюда расширение берёт прокси |

### Файлы в папке `data/`

## Что нужно знать про бесплатные прокси

Честный разговор, чтобы не было сюрпризов.

**Бесплатные прокси — это мусор.** Из 150 проверенных по HTTP работали 34, а по
HTTPS не работал ни один. Такой разброс — норма.

Из этого следуют ограничения, которые нельзя обойти кодом:

- **Прокси живут минуты.** Список, собранный час назад, бесполезен. Расширение
  переподключается автоматически, но список стоит обновлять
- **Это не анонимность.** Владелец прокси видит весь твой трафик. Публичный
  прокси — это как громкая труба, только ещё и с чужими руками рядом
- **Часть прокси вредоносная.** Подмена сертификата, сбор паролей, внедрение
  рекламы. Анализатор отсекает самые явные случаи, но не все
- **Не вводи пароли и не плати банковскими картами** через бесплатный прокси

### Что использовать вместо, если нужна настоящая приватность

| Инструмент | Что даёт |
|---|---|
| **Cloudflare WARP** | Бесплатный VPN, стабильный, от Cloudflare. Работает как локальный прокси на `127.0.0.1` |
| **Свой VPS** | Полный контроль, ~3–5 $/мес за сервер |
| **Платный прокси** | Стабильность и скорость за деньги |

## Безопасность и приватность

**Что расширение делает:**

- Хранит список прокси и настройки **только на твоём компьютере** (`chrome.storage.local`)
- Никуда не отправляет историю посещений
- Списывается на публичные источники только за списками прокси (если включён режим «Авто»)
- Блокирует утечку настоящего IP через WebRTC

**Разрешения расширения:**

| Разрешение | Зачем |
|---|---|
| `proxy` | Управлять прокси-соединением |
| `storage` | Хранить список и настройки локально |
| `alarms` | Периодические проверки |
| `privacy` | Блокировка WebRTC-утечек |

**Чего расширение не делает:**

- Не собирает и не передаёт историю просмотров
- Не читает содержимое страниц
- Не отправляет телеметрию

**Важно про fail-safe:** если режим включён и прокси умер, браузер может какое-то
время работать напрямую. Расширение это отслеживает и переподключается, но знай
про такую возможность.
